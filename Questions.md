3. How would you explain concepts like polymorphism and inheritance to a computer science student?
- Let's look at a sample answer to this question and I'll be right back with some feedback. - Inheritance lets us inherit different attributes and methods from another class. Polymorphism uses those methods to perform different tests. This allows us to perform a single action in different ways. So you can create a parent class that has several definitions of data types and functions that can be used by the child class that inherit from the parent class, hence the name. These child classes can then override some of the definitions of the data types and functions. Polymorphism then lets you programmatically decide which data types and functions to use. For example, think of a parent class called season that has a method called our day is hot, so that the method reflects the question that's answered when invoked from elsewhere in the code. Subclasses of season could be summer, winter, fall and they all have their own implementation of our day is hot, to reflect that summers have hot days, winters have cold days and falls are mix. However, when you need to print something generic, like, it's a beautiful day, you could create that capability in the parent class instead of repeating that in each of the child classes. This is how inheritance allows for efficiency and so then when you want to print a message that's customized to that particular season, you'd call the appropriate child class. This is how polymorphism uses automation to avoid redundant automation. It helps save time. Helps create clean code. Does that, is that good? You need more? - This was a very efficient and clinical answer. The very beginning of the answer explains conceptually that these concepts are intended to make programming more efficient. Associating polymorphism and inheritance to something everyone relates to like seasons is smart. All seasons have commonalities and differences making them a perfect use case. As an aside, showing how you can cluster a common code in the parent class while letting child classes handle special cases explains these concepts practically, this is useful since your audience is your student in this case. The candidate asked if they had any questions which is always a good thing since it allows you to course correct if required. Remember, a key part of problem solving is about getting from A to B efficiently and keeping the customer in mind starting with concepts, building a practical example, asking questions is part of that journey.

5. How do you measure success for yourself technically?
- This question aims at helping managers assess maturity in an engineer. Too often, technically gifted engineers confuse effort for impact and complexity for value. In college, you may get partial credit if you show your work, but from the customer standpoint in most cases, either your product works or it doesn't. A hiring manager will want to know whether you can set measurable goals for success and then work towards those goals. This is key in making sure that you can be self-directed, stay focused, and deliver on your promises. This is how you could structure an answer. First, define the problem. Clearly define what you wish to build, for whom, why, and what the value to the end user would be. You cannot define or measure success unless you understand your objective. Second, identify stakeholders and customers. Define the problem through the lens of how it affects someone or something. Then articulate what metrics you would use to define success and how you would track those metrics. Third, explain how you would approach and evaluate effectiveness. Explain your approach and desired end result. Then describe how you'd verify that your approach produced the outcomes you had intended to all along. Finally, touch on have you ensured that everyone agrees with your definitions of success and that there is buy-in on all stakeholders for the end results. Execution is a critical part of engineering, but the other part is agreement on the goal. Being able to connect the dots and making sure that you're achieving the intended outcome rather than some surprising outcome is equally important. This question tests that vital end-to-end skill that combines people skills, technical skills, and execution skills all at once.
